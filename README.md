# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные
В приложении используются две сущности, которые описывают данные, — товар и покупатель

### Интерфейс IProduct
**Назначение:** описывает товар магазина.

**Свойства:**
- id: string — уникальный индентификатор товара;
- description: string — описание товара;
- image: string — путь к файлу с изображением товара;
- title: string — название товара;
- category: string — категория товара;
- price: number | null — цена товара. Принимает null, если цена на товар отсутствует.


### Интерфейс IBuyer
**Назначение:** описывает данные покупателя для оформления заказа.

**Свойства:**
- payment: TPayment — способ оплаты;
- email: string — емайл покупателя;
- phone: string — телефон покупателя;
- address: string — адрес доставки.

### Тип TPayment
**Назначение:** определяет допустимые способы оплаты.  
**Значения** `"card" | "cash" | undefined` - возможные способы оплаты.

### Интерфейс IProductResponse
**Назначение:** описывает формат ответа сервера при запросе списка товаров.

**Свойства:**
- total: number - сумма заказов;
- items: IProduct[] - массив с идентификаторами товаров.

### Интерфейс IOrderRequest
Наследует все свойства интерфейса `IBuyer` и добавляет два новых свойства.
**Назначение:** описывает формат данных для отправки заказа на сервер.

**Свойства:**
- total: number - сумма заказов;
- items: string[] - массив с идентификаторами товаров.

### Интерфейс IOrderResponse
**Назначение:** описывает формат ответа сервера после успешного оформления заказа.

**Свойства:**
- id: string - уникальный индентификатор товара;
- total: number - сумма заказов.

## Модели данных

### Класс Products
**Назначение:** хранение товаров, которые можно купить в приложении.

**Конструктор:**
`constructor(products: IProduct[])` - принимает массив товаров за хранение, которых он отвечает.

**Генерируемые события:**
- `products:changed` - генерируется при изменение каталога товаров;
- `selectedProduct:changed` - генерируется при изменение выбранного для просмотра товара.

**Поля:**
- `private products: IProduct[]` - хранит массив всех товаров;
- `private selectedProduct: IProduct | undefined` - хранит товар, выбранный для подробного отображения.

**Методы:**
- `getProducts(): IProduct[]` - получение массива товаров из модели;
- `setProducts(products: IProduct[])` - сохранение массива товаров полученного в параметрах метода;
- `getSelectedProduct(): IProduct | undefined` - получение товара для подробного отображения;
- `setSelectedProduct(selectedProduct: IProduct | undefined)` - сохранение товара для подробного отображения;
- `getProductById(id: string): IProduct | undefined` - получение одного товара по его id.

### Класс ShoppingCart
**Назначение:** хранение товаров, которые пользователь выбрал для покупки.

**Конструктор:**
`constructor(products: IProduct[])` - принимает массив товаров, которые будут храниться в корзине.

**Генерируемые события:**
- `basket:changed` - генерируется при изменение содержимого корзины.

**Поля:**
- `private products: IProduct[]` - хранит массив товаров, выбранных покупателем для покупки.

**Методы:**
- `getProducts(): IProduct[]` - получение массива товаров, которые находятся в корзине;
- `addProduct(product: IProduct)` - добавление товара, который был получен в параметре, в массив корзины;
- `removeProduct(product: IProduct)` - удаление товара, полученного в параметре из массива корзины;
- `clear()` - очистка корзин;
- `getTotalPrice(): number` - получение стоимости всех товаров в корзине;
- `getProductCount(): number` - получение количества товаров в корзине;
- `containsProduct(id: string): boolean` - проверка наличия товара в корзине по его id, полученного в параметр метода.

### Класс Buyer
**Назначение:** хранение данных покупателя, которые указываются при оформлении заказа.

**Конструктор:**
`constructor()` - инициализирует объект покупателя с пустыми значениями.

**Генерируемые события:**
- `buyer:changed` - генерируется при изменение данных покупателя.

**Поля:**
- `private buyer: IBuyer` - хранит массив с данными покупателя.

**Методы:**
- `getData(): IBuyer` - получение всех данных покупателя;
- `setData(buyer: Partial<IBuyer>)` - общий метод для сохранения данных в модели. Можно сохранить одно значение, либо несколько;
- `clear()` - очистка данных покупател;
- `validate()` - валидация данных.

**Конструктор:**
`constructor(api: IApi)` - принимает объект, реализующий интерфейс IApi.

**Поля:**
- `private api: IApi` - хранит объект с данными запроса.

## Слой представления

### Класс Header

**Назначение:** Отвечает за отображение кнопки корзины и счетчика товаров в шапке сайта.

**Конструктор:**
`constructor(protected events: IEvents, container: HTMLElement)` - принимает брокер событий и контейнер, содержащий элементы управления корзиной.

**Генерируемые события:**
- `basket:open` — генерируется при клике на кнопку корзины, сообщает о необходимости открыть корзину.

**Поля:**
- `protected counterElement: HTMLElement` - хранит элемент счетчика;
- `protected basketButton: HTMLButtonElement` - хранит элемент кнопки корзины.

**Сеторы:**
- `set counter(value: number)` - устанавливает значение счетчика.

### Класс Gallery

**Назначение:** Отвечает за отображение каталога товаров в виде галереи.

**Конструктор:**
`constructor(container: HTMLElement)` - принимает контейнер галереи, в котором будут отображаться карточки товаров.

**Поля:**
- `protected catalogElement: HTMLElement` - хранит элемент галереи.

**Сеторы:**
- `set catalog(items: HTMLElement[])` - заменяет все карточки товаров в галерее на переданные элементы.

### Класс Modal

**Назначение:** Отвечает за отображение модального окна и его содержимого.

**Конструктор:**
`constructor(container: HTMLElement)` - принимает контейнер, содержащий элементы модального окна.

**Обработка событий закрытия:**
1. По клику на кнопку «Закрыть» - вызывается метод `close()`;
2. По клику вне модального окна - проверяется цель события. Если клик был именно по контейнеру (а не по его дочерним элементам), вызывается метод `close()`.

**Поля:**
- `protected contentElement: HTMLElement` - хранит элемент содержимого;
- `protected buttonElement: HTMLButtonElement` - хранит элемент кнопки закрытия.

**Сеторы:**
- `set content(item: HTMLElement)` - заменяет содержимое модального окна.

**Методы:**
- `open(): void` - добавляет класс `modal_active` модальному окну;
- `close(): void` - удаляет класс `modal_active` у модального окна.

### Класс Success

**Назначение:** Отвечает за отображение содержимого успешного оформления заказа с информацией о списанной сумме.

**Конструктор:**
`constructor(protected events: IEvents, container: HTMLElement,)` - принимает брокер событий и контейнер, содержащий элементы для отображения успешного оформления заказа.

**Генерируемые события:**
- `succes:close` — генерируется при клике на кнопку «за новыми покупками», сообщает о завершении просмотра успешного оформления.

**Поля:**
- `protected totalPriceElement: HTMLElement` - хранит элемент для отображения итоговой суммы заказа;
- `protected successButton: HTMLButtonElement` - хранит элемент кнопки «За новыми покупками».

**Сеторы:**
- `set totalPrice(value: number)` - устанавливает cписанную сумму.

**Сеторы:**

- `set category(value: string)` - устанавливает категорию товара.

**Сеторы:**
- `set image(value: string)` - устанавливает изображение товар;

**Сеторы:**

### Класс Order

## Слой презентер

Презентер реализован в файле `main.ts` как набор обработчиков событий. Его задача - управлять логикой взаимодействие между моделями данных и представлениями. Такой подход выбран потому, что приложение одностраничное, и одного презентера достаточно для управления всей логикой страницы.

**Список обрабатываемых событий:**
1. События от моделей данных:
`products:changed` - изменение каталога товаров;
`selectedProduct:changed` - изменение выбранного для просмотра товара;
`basket:changed` - изменение содержимого корзины;
`buyer:changed` - изменение данных покупателя.
2. События от представлений:
`card:select` - выбор карточки для просмотра;
`basket:add` - нажатие кнопки покупки товара;
`basket:delete` - нажатие кнопки удаления товара из корзины;
`basket:open` - нажатие кнопки открытия корзины;
`order:open` - нажатие кнопки оформления заказа;
`order:submit` - нажатие кнопки перехода ко второй форме оформления заказа;
`contacts:submit` - нажатие кнопки оплаты/завершения оформления заказа;
`formData:changed` - изменение данных в формах;
`success:close` - закрытие окна c сообщением об успешной оплате.
